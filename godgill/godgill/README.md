# 갓길 (Gatgil) — 안전 경로 추천 앱 MVP

천안역 반경 1.5km를 대상으로, 이동자 유형별 가중치를 반영해 "안전도 지표 기반" 경로를 추천하는 MVP입니다.
지도교수 권고에 따라 웨어러블/SOS/공공기관 자동알림은 이번 MVP 범위에서 제외했습니다.

## ⚠️ 팀원 작업물과의 관계 (중요, 꼭 읽어주세요)
팀원이 별도로 올린 `2026.09-12-GODGILL` 프로젝트(패키지 `com.safewalk`)는 **이 프로젝트와 다른 별개의
안드로이드 앱**입니다 (Jetpack Compose + 카카오 벡터맵 SDK + 모바일/웨어러블/백엔드 모노레포 구조로,
원래 기획의 로그인·웨어러블까지 포함한 전체 범위를 대상으로 함). 패키지명·UI 프레임워크·지도 SDK·
minSdk가 전부 달라 파일을 그대로 옮기면 빌드가 깨집니다.

그래서 **두 프로젝트를 합치는 대신, 팀원이 검증해 둔 실제 데이터 소스 3가지만 이 프로젝트(OSMDroid
기반, XML/ViewBinding)에 맞게 이식**했습니다:
- ✅ **보안등 데이터** — 네트워크 API 추정 호출 대신, 팀원이 확보한 실제 CSV(`보안등정보_천안시.csv`)를
  그대로 assets에 포함해서 사용 (`StreetlightProvider.kt`)
- ✅ **CCTV 데이터** — 충남 빅데이터 포털 실제 다운로드 URL과 파싱 로직 이식 (`CctvProvider.kt`),
  안전시설 세 번째 타입(🔵CCTV)으로 추가됨
- ✅ **위험구역(행정안전부 생활안전지도) WMS** — 좌표별 숫자가 아니라 이미지 한 장을 반환하는 API라서,
  안전도 **계산에는 넣지 않고** 지도 위에 켜고 끌 수 있는 **참고용 오버레이**로만 사용 (`SafeMapWmsClient.kt`)

로그인 화면·웨어러블·백엔드 서버는 이번 MVP 범위(지도교수 권고로 좁힌 범위)와 맞지 않아 가져오지
않았습니다. 다만 **로그인 화면은 실제 인증 없이 "구현만 보여주는" 형태로 이 프로젝트에 직접
새로 만들어 넣었습니다** (아래 "화면 구성" 참고). 두 프로젝트 중 최종 제출용을 어느 쪽으로 할지,
혹은 이 저장소 구조에 팀원 코드를 정식으로 모듈 분리해서 합칠지는 팀 논의가 필요합니다.

## 화면 구성
1. **로그인 화면** (`LoginActivity`, 앱 실행 시 처음 뜨는 화면) — 아이디/비밀번호 입력 후 "로그인"
   또는 "게스트로 계속하기"를 누르면 바로 지도 화면으로 이동합니다. **실제 인증 서버 연동은
   없고**, 입력값이 비어있지 않은지만 확인합니다 (데모/화면 시연용).
2. **지도 화면** (`MainActivity`) — 실제 경로 추천 기능 전체

## API 키
루트 폴더의 `local.properties`에 카카오 키는 이미 채워져 있습니다. 나머지는 비어있으면 해당
기능만 자동으로 비활성화(영향 없음)되고 나머지는 정상 동작합니다.
```
KAKAO_REST_API_KEY=발급받은_카카오_REST_API_키       # 이미 채워짐
VWORLD_API_KEY=발급받은_브이월드_인증키               # 비어있으면 개방감 항 자동 0 처리
DATA_GO_KR_API_KEY=발급받은_공공데이터포털_서비스키    # 현재 미사용 (보안등은 CSV로 대체됨, 예비용)
SAFEMAP_SERVICE_KEY=발급받은_생활안전지도_서비스키     # 비어있으면 위험구역 오버레이 토글이 꺼짐
```
- 카카오: 디벨로퍼스 콘솔 [내 애플리케이션] > 갓길 앱 > [제품 설정] > [카카오맵] "사용 설정" 필요
- 브이월드: vworld.kr 회원가입 → [오픈API] > [인증키] 발급 (무료)
- 생활안전지도: safemap.go.kr 오픈API 신청 후 서비스키 발급 (팀원이 이미 발급받았을 수 있음 — 확인해서 공유받기)
- 이 파일은 `.gitignore`에 포함되어 있어 **Git에는 올라가지 않습니다.** 팀원이 새로 clone하면
  본인 `local.properties`에도 위 네 줄을 직접 채워야 합니다.

## 안전도 점수 계산 방식
안전도 점수는 다섯 가지를 함께 반영합니다:
1. **목업 위험구역 회피** — 범죄주의구간 등을 흉내낸 가상의 위험구역에서 멀수록 높은 점수
2. **실제 안전시설 근접도(거리 기반)** — 가장 가까운 안전시설까지 거리에 비례해 가산점 (150m 이내, 최대 +0.15)
3. **실제 안전시설 밀집도(개수 기반)** — 150m 이내 안전시설이 몇 개 몰려있는지도 함께 반영 (3개
   이상이면 만점, 최대 +0.10). 김찬진·신동화(2025, 한국컴퓨터종합학술대회)의 "개수 기반 안전
   가중치" 방식을 참고해 거리 기반 항과 별도로 추가함 — 편의점 1곳만 있는 구간과
   편의점+지구대+CCTV가 몰려있는 구간을 구분하기 위함
4. **개방감 지수** — 브이월드 건물 데이터(높이·위치)로 "도로가 건물 사이에서 얼마나 트여있는가"를
   계산 (인접 건물까지 거리 ÷ 평균 높이, 30m 이내 건물 기준). CPTED의 "자연적 감시" 개념을 기하학적으로
   근사한 값으로, AI의 주관적 판단이 아니라 재현 가능한 수치 계산입니다.
   - **높이 데이터가 없는 건물**: 층수 필드가 있으면 "층수 × 3m(평균 층고)"로 추정해서 사용하고,
     층수도 없으면 계산에서 완전히 제외합니다.
   - **표본이 너무 적을 때**: 구간 30m 이내에 높이(실측+추정) 있는 건물이 2개 미만이면
     신뢰할 수 없다고 보고 이 항을 0으로 처리합니다 (억지로 평균 내지 않음).
   - 앱 상태 텍스트에 "건물 N개 반영(실측 X·추정 Y·제외 Z)"로 커버리지를 항상 보여줍니다.
5. **시간대별 조도** — 앱 실행 시각(06:00~18:00=주간, 그 외=야간) 기준으로 자동 전환됩니다.
   - **야간**: 보안등 밀도 — 구간 30m 이내 보안등 3개 이상이면 만점. 팀원이 확보한
     **충청남도 천안시 보안등정보 CSV**(`app/src/main/assets/보안등정보_천안시.csv`)를 번들해서
     사용하며, 네트워크 호출이 없어 항상 안정적으로 동작합니다.
   - **주간**: 실측 일조 데이터 대신 개방감 지수로 근사 (향후 브이월드 일조권 분석 API로 대체 가능)

⚠️ 브이월드 건물 레이어명·필드명은 코드 작성 시점에 문서로 100% 확정하지 못해 추정치가
들어있습니다 (`VWorldBuildingProvider.kt`의 TODO 주석 참고). 실제 키 발급 후 문서 대조해
맞춰야 정상 동작합니다 — 그 전까지는 실패 시 자동으로 빈 데이터로 처리되어 앱이 멈추지는 않습니다.

## 안전 가중치 슬라이더
하단 **"안전 가중치"** 슬라이더(0.00~1.00, 기본 0.55)로 A* 비용함수의 안전 가중치(w)를 직접
조절할 수 있습니다. 안전경로가 화면에 표시된 상태에서 슬라이더를 조절하면, 손을 뗄 때 그 값으로
자동 재계산되어 다시 그려집니다 (최단경로는 가중치와 무관해 영향 없음).

## 경로 색상
경로는 구간별 안전도 그라데이션 대신, **최단경로=빨강 / 안전경로=초록** 두 가지 단색으로 표시합니다
(광운대 논문의 최단=빨강·안전=파랑 2색 구분 방식을 참고해, 앱 기본 색상과 통일되도록 초록으로 사용).

앱 시작 시 대상지역 전체의 편의점/지구대·파출소/CCTV 좌표를 미리 불러와 반영하기 때문에,
목업 위험구역이 없는 구간에서도 실제 안전시설이 많은 길을 따라가는 쪽이 안전경로로 더 잘 선택됩니다.

## 위험구역 오버레이 (행정안전부 생활안전지도)
하단 **"⚠️ 위험구역 표시"** 체크박스를 켜면, MVP 대상지역(1.5km) 전체를 덮는 위험도 이미지를
지도 위에 겹쳐 보여줍니다 (팀원이 검증한 `SafeMapWmsClient` 이식).

- 이 API는 좌표별 숫자가 아니라 **PNG 이미지 한 장**을 반환하기 때문에, 안전도 점수 계산(A*)에는
  직접 넣지 않았습니다. 계산은 여전히 목업 위험구역 + 안전시설 + 개방감 + 조도로 이뤄지고,
  이 오버레이는 그 계산 결과를 **사용자가 눈으로 참고/대조**하는 용도입니다.
- `SAFEMAP_SERVICE_KEY`가 비어있으면 체크박스를 켜도 토스트 메시지만 뜨고 켜지지 않습니다.
- OSMDroid에는 Google Maps의 GroundOverlay 같은 기본 클래스가 없어서, 위경도 범위에 비트맵을
  고정해서 그리는 `WmsGroundOverlay`를 직접 구현했습니다 (`ui/WmsGroundOverlay.kt`).

## 실제 도로를 따라가는 경로 (OSM 도로망)
기존 150m 격자 목업 대신, 앱 실행 시 **OpenStreetMap(Overpass API)**에서
천안역 반경 1.5km의 실제 보행자 도로망을 받아와 그 위에서 A*를 계산합니다.
- 별도 API 키가 필요 없는 공개 API입니다.
- 안전도 점수는 기존 위험구역 목업 로직을 그대로 재사용해, "격자냐 실도로냐"만 바뀌고
  안전도 계산 기준은 동일합니다.
- 앱 시작 시 몇 초간 "도로 데이터를 불러오는 중입니다..."가 뜨는데, 이 동안 경로 버튼은 비활성화됩니다.
- **네트워크 실패 시(Overpass 서버 지연/오류 등) 자동으로 기존 격자 목업으로 대체**되어 앱이 멈추지 않습니다.
  이 경우 토스트 메시지로 알려줍니다.

## 사용법
1. 상단 "출발지 검색"에 장소명을 입력하고 검색 버튼 클릭 (예: 천안역)
2. "도착지 검색"에도 장소명을 입력하고 검색 버튼 클릭
3. **"최단경로"** 또는 **"안전경로"** 버튼을 누르면 그 즉시 해당 경로가 계산되어 지도에 표시됨
   (결과는 하단에 "최단 500m·6분·81점 | 안전 610m·8분·93점" 형태로 한 줄 요약, **"자세히 ▼"**를
   누르면 상세정보 펼쳐짐)
4. **안전경로를 눌렀을 때만** 경로 주변(200m 이내) 안전시설이 조회됨. 두 카테고리를 체크박스로
   따로 켜고 끌 수 있음: **🏪🚔 편의점·치안시설**(편의점+지구대/파출소), **📹 CCTV**
   (재조회 없이 바로 지도에 켜고 끔)
5. 하단 **"위험구역 표시"** 체크박스로 생활안전지도 위험도 이미지를 언제든 겹쳐볼 수 있음 (경로 계산과 무관)
6. 출발지/도착지를 다시 검색하면 이전에 그려진 경로/안전시설은 자동으로 지워짐

검색/안전시설 조회는 카카오 로컬 API(키워드 검색, 카테고리 검색)를 사용하며,
MVP 단계에서는 장소 검색 시 정확도 1순위 결과를 그대로 사용합니다
(검색 결과 여러 개 중 선택하는 UI는 다음 단계 개선 사항).

## 이동자 유형(학생/여성/고령자/교통약자) 가중치는 잠시 제외했습니다
`model/RouteMode.kt`에 유형별 가중치 값은 그대로 남아있고, `MainActivity`의
`defaultSafetyWeight` 상수(현재 0.4, RouteMode.STANDARD와 동일)만 안전경로 계산에 쓰입니다.
나중에 유형 선택 UI를 다시 붙이려면 이 상수 대신 스피너 선택값을 넘기면 됩니다.

## 구조
- `model/` : Node, Edge, RouteMode(유형별 안전 가중치)
- `route/SafetyDataProvider.kt` : 천안역 반경 1.5km 격자 그래프 + 위험구역 목업 데이터 생성
- `route/AStarRouter.kt` : 거리 + 안전도 가중 A* 탐색
- `MainActivity.kt` : OSMDroid 지도 UI (API 키 불필요)

## 현재는 목업 데이터입니다
`SafetyDataProvider`의 안전도 점수는 실제 공공데이터가 아니라 재현 가능한 패턴으로 생성한 목업입니다.
다음 단계에서 아래 데이터로 교체/결합하면 됩니다:
- 경찰청 범죄주의구간 API
- 고령보행자 사고다발지역 데이터
- 교통약자 이동경로 데이터
- 도로위험도지수
- 사용자 실시간 제보(크라우드소싱)
